# deep_learning_archi.ipynb (Tier 4, LSTM-based) only:
#
# torch==2.4.1, NOT the more "obvious" 2.2.1/2.3.1 -- both were tried first
# (matching what was already installed elsewhere in this environment / the
# next few point releases) and BOTH fail at import time against this file's
# numpy==2.5.2 pin: `UserWarning: Failed to initialize NumPy: _ARRAY_API not
# found` followed by `RuntimeError: Numpy is not available` the moment
# torch.from_numpy()/.numpy() is used (which this notebook's channel
# encoding and streaming inference both do constantly). This is the exact
# same category of bug as the numpy/scipy ABI mismatch already documented
# in EXPERIMENTS.md's Scope section 3 (a package built against NumPy 1.x's
# C-API breaking under NumPy 2.x) -- confirmed empirically in a disposable
# throwaway venv (installed each candidate version, ran a real
# torch.from_numpy()/.numpy() round-trip plus an nn.LSTM +
# pack_padded_sequence/pad_packed_sequence forward pass, not just an import
# check) before pinning here, precisely to avoid repeating that incident.
# torch==2.4.1 is the first version confirmed to work cleanly against
# numpy==2.5.2 in that check; verify again if this pin is ever bumped, using
# the same round-trip + LSTM check, not just "install and import".
